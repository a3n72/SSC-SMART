SMART on FHIR 授權流程逐步演示 Standalone Launch

每一步按一次按鈕，畫面會顯示 App 實際送出與收到的內容。預設連到 SMART Health IT 公開 Launcher，全部是模擬病人資料。

0設定

Standalone Launch 直接使用預設值即可。若從 Launcher 以 EHR Launch 開啟本頁，iss 與 launch 會自動帶入。

1Discovery：詢問 FHIR Server 的授權端點

App 只知道 FHIR Server 網址，先讀取 .well-known/smart-configuration 取得授權端點與 token 端點。

2產生 PKCE 與 state

code_verifier 是 App 自己保管的隨機字串，code_challenge 是它的 SHA-256；state 用來確認導回的回應屬於這次請求。

3組出授權網址，把使用者導向授權伺服器

App 不經手帳號密碼；登入、選病人、同意授權都在授權伺服器的頁面上完成。

4導回 App：收到授權碼 code

授權伺服器把瀏覽器導回 redirect_uri，網址上帶著 code 與 state。code 只能用一次，而且很快過期。

5用 code 與 code_verifier 換 access token

App 對 token 端點送 POST。回應除了 access_token，還有 SMART 的 context：這次授權針對哪一位病人。

6帶著 access token 呼叫 FHIR API

之後就是第 4 堂練過的 FHIR API，只是每個請求多了 Authorization: Bearer 標頭。
